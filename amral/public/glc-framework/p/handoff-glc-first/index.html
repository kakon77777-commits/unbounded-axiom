v1.0 方案 B 交接文件

GLC 優先研究交接與實行建議:GLC → {GCC, USRT, USEG}

核心修訂:把研究順序從「前三層 → GLC 封頂」倒過來,改成「GLC 先行 → 其餘三層建立於 GLC 之上」。理由是若 GLC 未先嚴格定義,GCC 會缺失目標函數、USRT 會缺失完成態、USEG 會缺失「決策充分」標準。第一版 GLC(記為 GLC₀)必須「資源中立」——不能一開始就要求多項式時間,否則等於把 GCC 偷偷塞進 GLC 的基底定義。拆成五條核心公理,並要求至少 5 個正例、5 個反例與初步形式化才算 GLC Foundation v1.0 完成。

長期研究交接／執行順序修訂文件;目前定位為啟發式 Characterization Program,不宣稱已證明 P=NP 或 P≠NP — 文件自陳的性質,原樣照登。
