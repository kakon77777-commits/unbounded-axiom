Phase 1 v0.2 收斂裁決

v0.1 已獨立重現 Algorithm 2 的兩個代表分支;v0.2 把工作從「結果重現」升級成「版本化證書回歸」——新增舊 fixture(5月22日)與現行 fixture(6月3日)的完整差分、官方 discrepancy report 的獨立對抗式語料庫、false-positive/unknown/timeout/testing-only 的受控失敗字典、500K 重跑前的 soundness preflight、「版本回歸不等於數學拒絕原因」的資料分層、以及可執行的 regression test。最重要的發現:舊 fixture 有 25 條曲線,現行 fixture 只剩 12 條——現行集合是舊集合的純子集,保留 12、移除 13、新增 0。這個結果直接指向一個紀律結論:theorem-producing code 不能只保存最終成功清單,必須保存數學語義的版本歷史。文件把差分拆成兩種對抗式語料庫——Corpus A(Version Regression)只回答「哪些曲線曾被舊版官方 pipeline 放行,但現行版不再放行」,只證明 membership change,不能自動推斷每條的數學拒絕原因;Corpus B(Explicit Discrepancy)是官方 discrepancy_report.txt 對四條曲線逐 predicate 列出的現行拒絕理由,這才是真正的 theorem-level 對抗式語料庫。最後建立新閘門:進入 500K 全規模重跑前,必須同時通過現行正向 fixture、歷史版本回歸、與明確 discrepancy corpus 三項。

舊 fixture 25 條 → 現行 fixture 12 條:保留12、移除13、新增0(純子集) — 包內文件自陳的階段性狀態,原樣照登。
