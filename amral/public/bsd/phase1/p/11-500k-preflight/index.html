500K Preflight

文件開頭就聲明本 runtime 沒有獨立重算官方 500K 輸出。放大規模前必須依序完成五步:鎖定 Sage/LMFDB/Git SHA/descent backend 這些環境變數;在 conductor<150 做精確重播;對舊版才有的 13 條曲線做 first-failure 重播;對 07 篇(即將上線)四條 discrepancy 曲線做精確拒絕重播;最後才能跑 conductor<500000。500K run 完成後必須輸出七項機器可讀 artifact:passed.csv、failed.csv、unknown.csv、predicate_trace.jsonl、descent_certificates/、run_manifest.json、hashes.txt——文件特別強調 unknown.csv 不能丟掉,否則 timeout 或 backend failure 會被誤讀成數學拒絕,這正是 10 篇 S3 條款的具體實作要求。最後定義「成功」的精確標準,明確不是「最後 count 很接近」這種模糊判定,而是四件事同時成立:final set exact(最終集合精確,不是約略)、stage counts reproducible(每個 filter 階段的數量可重現)、adversarial corpus stable(09 篇的對抗式語料庫結果穩定)、certificate semantics stable(證書語義穩定,不隨版本漂移)。

成功 = final set exact + stage counts reproducible + adversarial corpus stable + certificate semantics stable(四者同時) — 包內文件自陳的階段性狀態,原樣照登。
