RH-W-18:統一證書後端與單一驗證入口

W-05 到 W-17 逐步累積的證書 schema、依賴與完整度並不一致 — 本包建立單一 CLI(rhcert.py)與五段信任詞彙,重新逐一原生重放每一輪的 verifier。結果不是全綠:W-06 因公開目錄缺一個 2×2 JSON 被標為 LEGACY_INCOMPLETE,W-14 因原推導漏項被標為 SUPERSEDED_RECERTIFIED——這正是後端存在的理由。

RH_CLAIM = False — 包內驗證器自己輸出的宣稱狀態,原樣照登。統一 manifest 固定 allowed_global_conclusion=FINITE_CERTIFICATE_BACKEND_ONLY;若 manifest 被改成 RH_CLAIM=true,即使重新計算 hash,驗證仍拒絕。
