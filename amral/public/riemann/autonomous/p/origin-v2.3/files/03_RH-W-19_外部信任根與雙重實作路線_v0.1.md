# RH-W-19：外部信任根與雙重實作路線

## 自我認證的界線

SHA-256 能回答「檔案是否與索引相同」，不能單獨回答：

- 索引由誰發布；
- verifier 是否正確；
- generator 與 verifier 是否共用同一錯誤；
- 發行後是否被整套替換。

## Batch 02 建議的信任升級

### 第一層：簽章 release manifest

對 release manifest 建立離線簽章，網站只公布簽章、commit 與 ZIP digest，不把私鑰放入研究工具鏈。

### 第二層：可重現建置

從固定 source、固定 Python 版本與依賴 lockfile 重建證書，要求兩次建置得到相同 canonical JSON digest。

### 第三層：獨立 verifier

至少建立一個不同語言或不同算術後端，例如：

- Python `Fraction` verifier；
- Rust big-rational verifier；
- Lean 產生的小型 kernel checker。

### 第四層：外部鏡像

在網站、GitHub release 與 DOI／長期封存站同步公布 digest。任一位置被替換時可由其他鏡像辨認。

## 不可過度宣稱

即使完成以上四層，也只能提升 finite certificate 的供應鏈可信度，不會自動把有限維 Weil 結果提升為 RH 證明。
