# RH-W-18：統一證書後端與單一驗證入口

**節點**：`RH-W-18-CERTIFICATE-BACKEND-CONSOLIDATION`  
**日期**：2026-07-24  
**定位**：Batch 01 的證書工程整併；不是黎曼猜想的證明或反證。

## 摘要

RH-W-05 至 RH-W-17 已逐步形成多種證書：有限維 Weil 矩陣、prime-power 腔室、廣義譜下界、固定 witness 上界、混合正則性字典、參數管、三維盒與事件面切分。它們的數學內容可以相容，但歷史封包的 schema、依賴、輸出格式與完整度並不一致。

本輪建立共同後端：

```bash
python rhcert.py list
python rhcert.py verify
python rhcert.py verify --record RH-W-17
python redteam_backend.py
```

後端先檢查 SHA-256，再把每個歷史 verifier 放入暫存副本執行，避免 verifier 產生的輸出檔改動原證書。每個成功結果還必須同時包含預期狀態字串與 `RH_CLAIM=False`。

## 五種證書類別

1. `NUMERICAL_MATRIX`：有限維區間矩陣與 exact rational LDL 證書。
2. `PARAMETER_REGION`：連續參數盒、角點凸包與 Taylor 餘項。
3. `CHAMBER_COVER`：事件面切分、閉區間覆蓋與腔室鄰接。
4. `STRUCTURAL_IDENTITY`：activation order、正則性與核卷積身分。
5. `PROTOCOL_ONLY`：定義如何接受負 witness，但不宣稱已找到 witness。

## 狀態不是二元通過／失敗

- `VERIFIED`：封包內可以完整重放指定 verifier。
- `VERIFIED_WITH_LIMITATION`：可驗證部分成立，但不足以重建所有歷史輸入。
- `PROTOCOL_ONLY`：驗證協議通過自測，沒有目標數學 witness。
- `SUPERSEDED_RECERTIFIED`：舊推導被取代，結論由後續輪次重新證明。
- `LEGACY_INCOMPLETE`：缺少必要歷史輸入，不允許顯示成綠色。

這個狀態格比「所有輪次都成功」更重要，因為它把研究內容與封包品質分離。

## Claim firewall

統一 manifest 固定：

```json
{"RH_CLAIM": false, "allowed_global_conclusion": "FINITE_CERTIFICATE_BACKEND_ONLY"}
```

單一有限維正性、有限參數管或事件面覆蓋都不能被後端提升為 RH 結論。若 manifest 被改成 `RH_CLAIM=true`，即使重新計算檔案 hash，manifest 驗證仍拒絕。

## 本輪最重要的工程結果

W-18 並沒有把不同數學證書硬壓成同一個矩陣格式，而是統一它們的上層語義：

$$
\text{Artifact Identity}
\to
\text{Native Verification}
\to
\text{Normalized Claim Record}
\to
\text{Dependency Graph}
\to
\text{Claim Firewall}.
$$

因此未來新增證書類型時，可以保留原生 verifier，只需增加 adapter 與 manifest record，不必重寫所有歷史證書。
